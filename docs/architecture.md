# IssueDock 架构与数据契约

## 目标

IssueDock 为需要快速整理维护工作的个人提供一个小型任务看板，同时满足四项约束：

1. 不需要账号、服务器或网络连接；
2. 不加载外部脚本、字体、分析工具或 CDN；
3. 用户数据可导出、可检查并能在失败后恢复；
4. 源码足够小，贡献者可以在不安装依赖的情况下理解和验证。

多人协作、GitHub Issues 同步、提醒服务和跨设备同步是明确的非目标。

## 运行时结构

```text
index.html
  ├─ styles.css
  ├─ core.js   -> window.IssueDockCore
  └─ app.js    -> DOM、localStorage、文件导入/导出

core.js
  └─ 纯数据逻辑，可由浏览器和 Node.js 测试共用
```

项目没有构建步骤。`core.js` 在 Node.js 中通过 `module.exports` 暴露接口，在浏览器中挂载冻结的 `window.IssueDockCore` 对象。

## 数据流

1. `app.js` 从 `localStorage["issuedock.tasks.v1"]` 读取 JSON。
2. `core.parseBackup` 验证版本、任务数量、字段、枚举、时间、重复 ID 和总字节数。
3. 用户操作产生下一份完整任务数组。
4. `core.backup` 再次校验并序列化下一份数据。
5. `localStorage.setItem` 成功后，应用重新解析写入值并更新界面。
6. 其他标签页通过 `storage` 事件重新读取数据。

如果初始读取或跨标签页读取失败，应用进入“保存已暂停”状态，避免用空列表覆盖无法解析的旧数据。用户可以导入通过校验的备份恢复。

## 备份格式

版本 1 的外层格式如下：

```json
{
  "app": "IssueDock",
  "version": 1,
  "exportedAt": "2026-10-27T00:00:00.000Z",
  "tasks": [
    {
      "id": "task-id",
      "title": "任务标题",
      "project": "项目",
      "description": "描述",
      "status": "backlog",
      "priority": "medium",
      "createdAt": "2026-10-27T00:00:00.000Z"
    }
  ]
}
```

约束：

- `status`：`backlog`、`progress`、`done`
- `priority`：`high`、`medium`、`low`
- 最多 1000 项任务
- 备份文件最多 1 MiB
- 标题最多 160 字符，项目最多 80 字符，描述最多 5000 字符
- ID 在单个备份中必须唯一
- 时间必须可被 `Date.parse` 解析

未知字段会在校验后移除。改变数据格式时必须提高 `version` 并提供明确的迁移路径，不能静默改变版本 1 的含义。

## 信任边界

- 任务文本、项目名、标题和导入文件都视为不可信输入。
- 卡片使用 `textContent` 创建，不把用户文本交给 `innerHTML`。
- Markdown 导出会转义 HTML 和 Markdown 控制字符，并折叠换行。
- 导入文件先检查大小，再解析 JSON，再执行完整任务校验；确认替换前不会写入存储。
- 项目没有第三方运行时依赖，降低供应链面和网络数据泄露风险。

`localStorage` 不是安全存储。任何能在同一来源执行脚本的代码都可以读取任务，因此项目必须继续禁止外部脚本和不受控的内联脚本。

## 失败处理

| 失败 | 行为 |
| --- | --- |
| 初始存储无法解析 | 停止保存，显示“保存已暂停” |
| 写入超出配额或校验失败 | 保留原数据，显示错误，不更新内存状态 |
| 导入文件过大或无效 | 不替换现有任务 |
| 跨标签页写入无效数据 | 停止保存，提示其他页面数据无效 |
| 浏览器清理存储 | 数据不可恢复，需要用户重新导入备份 |

## 测试策略

- 单元测试覆盖备份往返、Unicode、筛选组合、重复 ID、非法枚举、字段限制、大小限制和 Markdown 转义。
- 浏览器冒烟测试通过 Chrome DevTools Protocol 驱动真实 Chromium，不引入测试框架依赖。
- 浏览器测试覆盖新增、编辑、状态切换、搜索、重载、导入、删除、键盘关闭、焦点保持、可访问名称、恶意文本、存储恢复和 320px 窄屏。
- CI 在 Node.js 22 与 24 上运行核心测试，并单独运行浏览器测试。

## 演进原则

- 能用平台原生能力解决的需求，不引入框架。
- 新功能必须先说明用户问题，并保持离线运行。
- 数据格式变更必须包含迁移、兼容性和失败测试。
- 重要交互变更必须增加浏览器回归测试。
- 不通过虚假使用量或自动化互动提高项目曝光。
